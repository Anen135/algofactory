# Как добавить уровень

Добавьте `Level` в массив `levels` в `src/content/levels/index.ts`. Порядок массива задаёт порядок карты и кнопки «Следующий уровень». ID должен быть уникальным и оставаться стабильным: он используется в LocalStorage.

```ts
{
  id: 'triple',
  name: 'Тройная мощность',
  topic: '11 / ПРАКТИКА',
  description: 'Умножьте входное число на 3.',
  hint: 'Source → Math A; Constant(3) → Math B. Операция *.',
  inputType: 'number',
  availableMachines: ['source', 'output', 'constant', 'arithmetic'],
  tests: [
    { input: 2, expected: 6 },
    { input: -4, expected: -12 },
    { input: 0, expected: 0 },
    { input: 1.5, expected: 4.5, hidden: true },
  ],
  medals: { machines: 4, operations: 16, ticks: 60 },
}
```

`inputType` — описание задания; runtime проверяет реальные DataValue и типы портов. Значение expected — один пакет, даже если это массив. Для каждого уровня нужен хотя бы один открытый тест и непустой общий набор. Видимые примеры не должны быть единственным способом проверить правильность: добавляйте скрытые крайние случаи.

## Доступные машины

Используйте зарегистрированные type IDs. Минимальный набор — Source и Output. Одна и та же Arithmetic реализует +, −, *, /, %. Не добавляйте отдельную Multiply без отдельной механики.

Задания проверяют поведение, а не точную форму решения. Например, прямое соединение тоже проходит задачу «вернуть исходную строку»; текст задания предлагает Split/Join ради обучения. Если требуется именно освоение конструкции, расширьте Level отдельным явно документированным правилом, а не скрытой проверкой геометрии.

## Tutorial

Необязательное поле `tutorial`:

```ts
[
  { text: 'Добавьте Source.', condition: 'machine', machineType: 'source' },
  { text: 'Создайте связь.', condition: 'connection' },
  { text: 'Запустите все тесты.', condition: 'completed' },
]
```

Условия читают состояние модели; координаты и renderer не используются. Для нового вида tutorial-события расширьте `TutorialStep` и обработчик в `src/ui/tutorial.ts`.

## Подтверждение проходимости

Создайте reference factory в тестах (пример — `src/core/test-factories.ts`), прогоните `runLevel` и убедитесь, что все открытые/скрытые тесты успешны. Reference factories не импортируются приложением. Проверьте, что неверное решение и решение, фиксирующее только первый пример, не проходят.

Пороги медалей сравните с результатом корректного решения. Метрики operations/ticks суммируются по всем тестам. Они дают дополнительную цель и не должны блокировать прохождение.

Общее число уровней UI берёт из массива. Обновите README и reference factories при расширении набора. Запустите typecheck, unit tests, build и браузерный сценарий перехода между уровнями.
