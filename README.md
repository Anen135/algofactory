# Data Factory

Браузерная 2D-игра для изучения программирования через фабрику данных. Постройте алгоритм из машин, соедините порты, проследите за пакетами, проверьте решение на открытых и скрытых тестах и откройте его эквивалент на Python.

Стек: TypeScript strict, Phaser 4, Vite, Vitest, HTML/CSS. React и сервер не требуются. Логика симуляции не зависит от Phaser и DOM.

## Запуск

Нужен Node.js 22.12+ или 24 LTS и npm.

```bash
npm install
npm run dev
```

Откройте адрес из терминала (по умолчанию `http://127.0.0.1:5173`).

```bash
npm run typecheck
npm test
npm run build
npm run preview
```

`npm test` запускает тесты ядра, уровней, состояния, сохранений и генерации кода. Если доступен Python 3, дополнительно выполняется настоящий сгенерированный Python для всех уровней. Эти дополнительные тесты пропускаются без Python; сама игра его не использует. Путь к интерпретатору можно задать через `PYTHON`.

## Как играть

1. Выберите задание на карте. Первый уровень сопровождается интерактивными подсказками.
2. Перетащите машину из каталога на поле. Нажатие на карточку тоже добавляет машину.
3. Потяните от выходного порта справа к входному слева. Можно нажать порты по очереди.
4. Выберите машину и настройте параметры справа. Constant принимает JSON: `2`, `"A"`, `true`, `[1,2]`.
5. RUN запускает выбранный открытый пример с анимацией, затем проверяет все тесты. Повторное нажатие ставит запуск на паузу.
6. «Шаг» выполняет ровно одно событие. После завершения нажмите «В редактор», чтобы изменить фабрику.
7. После успешных тестов переходите дальше. Фабрики и рекорды сохраняются в этом браузере автоматически.

Скорости: 0.25×, 0.5×, 1×, 2×, 4× и Instant. Instant пропускает анимацию при непрерывном запуске; Step остаётся наглядным даже с выбранным Instant.

| Управление | Действие |
| --- | --- |
| Мышь за корпус машины | Перемещение с привязкой к сетке |
| Правая/средняя кнопка или пробел + мышь | Панорама |
| Колесо / кнопки − и + | Масштаб |
| F | Вписать фабрику |
| Delete / Backspace | Удалить выбранную машину или связь |
| Ctrl+Z / Ctrl+Shift+Z | Undo / Redo |
| R / точка | RUN–Pause / Step |
| Esc | Отменить соединение / снять выделение |
| Ctrl+S | Сохранить локально |
| ⇩ / ⇧ над полем | Экспорт / импорт JSON текущего уровня |

Приоритетные размеры: 1920×1080 и 1366×768. Интерфейс также проверяется при 1100×700; мобильная компоновка не входит в MVP.

## Содержимое

Десять уровней: передача значения, удвоение, +10, сравнение с 10, чётность, Split/Join, разворот строки, Branch, фильтрация массива, палиндром.

12 типов машин: Source, Output, Constant, Arithmetic, Comparator, Split, Join, Stack, Queue, Branch, Filter, Memory. Multiply — операция `*` у Arithmetic.

Все задания доступны на карте. Для прохождения нужны все тесты; медали Compactness, Efficiency и Throughput необязательны.

## Браузерные тесты

```bash
npx playwright install chromium
npm run test:e2e
```

После сборки `npm run test:build` отдельно проверяет `dist/` через HTTP в подпапке `/algofactory/`: загрузку Phaser, редактор, сохранение после reload и отсутствие внешних ресурсов. Используется тот же `PLAYWRIGHT_CHANNEL`.

Можно использовать установленный Edge вместо загрузки Chromium (PowerShell):

```powershell
$env:PLAYWRIGHT_CHANNEL = 'msedge'
npm run test:e2e
```

Тесты сами запускают Vite или используют существующий сервер на порту 5173. Они проверяют drag/drop, соединения, перемещение, undo/redo, Step/Pause, живой инспектор, параметры, пакеты, удаление связей, камеру, Code View, сохранения и все десять уровней. Скриншоты и трассы ошибок — в `test-results/`.

## Статическая публикация

Публикация через ваш авторизованный GitHub CLI (`gh`) и PowerShell 7:

```powershell
# Один раз: создать публичный репозиторий, настроить Pages и опубликовать.
pwsh -File ./scripts/publish-pages.ps1 -Owner Anen135 -Repository algofactory -CreateRepository

# Повторная публикация после commit изменений:
pwsh -File ./scripts/publish-pages.ps1 -Owner Anen135 -Repository algofactory
```

Скрипт требует чистое рабочее дерево, запускает typecheck/tests/build, отправляет текущую ветку в origin, включает Pages с GitHub Actions, запускает нужный workflow, ждёт его завершения и проверяет HTTP-ответ сайта. Токен берётся из `gh auth login`, не сохраняется в проекте. Существующий чужой origin не заменяется, force-push не используется. `-NoWait` запускает публикацию без ожидания, `-SkipChecks` пропускает локальные проверки (workflow всё равно запускает тесты и сборку). Без `-Owner` используется текущий пользователь `gh`.

`npm run build` создаёт `dist/`. Загрузите содержимое этой папки на любой статический хостинг. Не открывайте `index.html` через `file://`: используйте HTTP-сервер.

Для ручной настройки без скрипта включите **Settings → Pages → Source: GitHub Actions**, затем запустите workflow **Deploy Data Factory**. Он собирает и публикует `dist/`. `base: './'` позволяет размещать игру в подпапке репозитория; маршрутизатор и настройка fallback не нужны. Автоматический запуск происходит только при изменении самого файла workflow (это также регистрирует Actions в новом репозитории); обычные изменения публикуются через скрипт или ручной запуск.

Сохранения привязаны к origin браузера. Для переноса между локальным адресом и опубликованной игрой экспортируйте JSON решения. Скрытые тесты не показываются в UI, но входят в статический JS bundle: это учебная игра, не защищённая соревновательная система.

## Структура

```text
src/core/             независимая симуляция, машины, граф и проверки
src/state/            редактор, история команд, управление запуском, persistence
src/renderer/         Phaser-сцена, камера, порты, линии и пакеты
src/ui/               HTML-панели, tutorial, обработчики UI
src/content/levels/   задания и наборы тестов
src/code/             промежуточное представление и генераторы кода
e2e/                  браузерные проверки Playwright
docs/                 архитектура, игровой дизайн и расширение проекта
```

## Границы MVP

Потоки конечны; машина обрабатывает буфер после закрытия всех подключённых входов. Графовые циклы отклоняются. Memory демонстрирует запись/чтение в пределах одного запуска и сбрасывается между тестами. Произвольные for/while, функции, рекурсия и вложенные границы потоков требуют следующего этапа control flow.

Python Code View поддерживает текущие машины. JavaScript экспортирует скалярные фабрики Source/Constant/Math/Compare/Output; для потоков UI предлагает Python. Code View показывает вычисление, а не воспроизводит анимацию или тики.
